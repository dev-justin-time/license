Licensing a repository

Public repositories on GitHub are often used to share open source software. For your repository to truly be open source, you'll need to license it so that others are free to use, change, and distribute the software.

Edit this doc

Choosing the right license

We created choosealicense.com , to help you understand how to license your code. A software license tells others what they can and cannot do with your source code, so it's critical to make an intentional decision.

Note on GitHub Public Repositories

If you publish your source code in a public repository on GitHub, according to the Terms of Service, other users of GitHub.com have the right to view and fork your repository. If you have already created a repository and no longer want users to have access to the repository, you can make the repository private. When you change the visibility of a repository to private, existing forks or local copies created by other users will still exist. For more information, see Setting repository visibility.

Determining the location of your license

Most developers place their license text in a top-level file named LICENSE.txt (or LICENSE.md or LICENSE.rst) in the root of the repository; here's an example standard structure:

Alternative in README:

Some projects specify their license in their README.md, such as: "This project is licensed under the terms of the MIT license." However, adding an independent license file ensures automatic GitHub API detection and UI badges.

When you search by a family license, your results will include all licenses in that family. For example, when you use the query license:gpl, your results will include repositories licensed under GNU General Public License v2.0 and GNU General Public License v3.0.

Detecting a license

GitHub uses Licensee, an open source Ruby gem that compares the repository's LICENSE file against known SPDX database signatures to automatically generate repo badges and power API insights.

licensee CLI Ruby Gem & API
View source
$ gem install licensee
$ licensee detect .

If your repository uses a license that is not recognized or not displaying clearly at the top of the repository page, it may contain multiple licenses or custom modifications. Simplify your LICENSE file and move secondary credits to README.

Applying a license to a repository

The built-in license template picker is presented when creating a new project on GitHub or manually creating a LICENSE file in the browser:

1

Navigate to Root

Click Add file → Create new file in your GitHub repository main branch.

2

Type LICENSE

In the filename field, enter LICENSE. The template button activates automatically.

3

Choose & Commit

Select your desired license from the dropdown, review year & fullname, and commit directly.
